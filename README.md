# Virentora

Статический сайт [virentora.com](https://virentora.com): услуги, демонстрационные работы, процесс, ориентиры стоимости и контакты. Интерфейс на русском и английском. Земля рисуется в браузере с помощью локальной Three.js; сервер приложения и сборщик для публикации не нужны.

## Структура

| Файл или папка | Назначение |
|---|---|
| `index.html` | Семантическая разметка и исходное содержимое страницы |
| `styles.css` | Общая система оформления, адаптивная компоновка и состояния элементов |
| `app.js` | Переводы RU/EN, меню, FAQ и управление интерфейсом |
| `earth.js` | Трёхмерная сцена Земли и управление её отрисовкой |
| `assets/` | Локальная Three.js, текстуры Земли, звёздный фон и другие ресурсы |
| `assets/ATTRIBUTION.md` | Источники и условия использования графики и библиотеки |
| `shots/` | Изображения демонстрационных проектов |
| `CNAME` | Существующий домен `virentora.com` для GitHub Pages |

Не открывайте страницу через `file://`: загрузке модулей и текстур нужен HTTP. Содержимое сайта не требует установки npm-пакетов.

## Локальный просмотр

В терминале VS Code откройте папку репозитория и запустите Python 3:

```powershell
Set-Location C:\projects\virentora
python -m http.server 4186 --bind 127.0.0.1
```

Откройте [локальный сайт](http://127.0.0.1:4186). Оставьте терминал работающим на время просмотра. `Ctrl+C` останавливает сервер. Если команда `python` недоступна, установите Python 3 или используйте имеющийся Python launcher: `py -m http.server 4186 --bind 127.0.0.1`.

Проверяйте внешний вид и прокрутку на широком экране и телефоне, обе языковые версии, меню с клавиатуры, FAQ, якоря, паузу движения и поведение без WebGL. Запуск локального сервера не публикует сайт в интернете.

## Изменение содержания

Основной русский текст находится в `index.html`, английский — в атрибутах `data-en` тех же элементов. Английские подписи доступности и описания изображений задаются через `data-aria-en` и `data-alt-en`. Динамические подписи кнопок, заголовок вкладки и meta description обновляются в `app.js`. После изменений проверяйте оба языка в браузере.

## Git и публикация

Репозиторий: [rapt228/virentora](https://github.com/rapt228/virentora). Основная ветка при подготовке этой версии — `main`. Файл `CNAME` сохраняет существующий домен; для обновления дизайна менять домен или DNS не нужно.

Это разные действия:

1. **Сохранение файлов** меняет локальную рабочую папку. Результат можно посмотреть через локальный сервер.
2. **Commit** фиксирует выбранные изменения в локальной истории Git. Сам по себе обычный локальный commit не обновляет GitHub и сайт.
3. **Push** отправляет коммиты в удалённый репозиторий. В VS Code команда **Sync Changes / Синхронизировать изменения** может включать получение и отправку коммитов; перед ней проверьте ветку и состав изменений.
4. **Публикация GitHub Pages** выполняется отдельно по настройкам репозитория. Если Pages настроен на ветку `main` и корневую папку, push в эту ветку запускает обновление сайта. Фактические настройки нужно проверить в **Settings → Pages**, результат — в **Actions / pages-build-deployment**.

Перед своим commit посмотрите `git status` и diff. В отправляемые изменения должны попасть не только HTML, но и используемые CSS, JavaScript, текстуры и остальные ресурсы. Не отправляйте секреты, локальные базы и временные файлы. После успешной публикации отдельно откройте [virentora.com](https://virentora.com) и проверьте загруженную версию, при необходимости обновив кеш браузера.

Наличие новой версии в этой папке не подтверждает, что она уже опубликована. Для текущего локального редизайна commit, push и изменение настроек публикации не являются частью автоматической подготовки файлов.
